# Student Outcome

| Criterio específico                                                                                                                     | Acciones realizadas | Conclusiones |
|-----------------------------------------------------------------------------------------------------------------------------------------|---------------------|--------------|
| Actualiza conceptos y conocimientos necesarios para su desarrollo profesional y en especial para su proyecto en soluciones de software. | **AV1:** El equipo aplicó Lean UX para formular el problema, las *assumptions*, las hipótesis y el Lean UX Canvas de CraveWallet; diseñó, registró y analizó seis entrevistas de *needfinding*; elaboró User Personas, User Journey Maps, Empathy Maps, User Task Matrix y Big Picture EventStorming. Además, transformó los hallazgos en 40 User Stories, 6 Technical Stories y 6 Spike Stories con criterios de aceptación, cuatro Impact Maps y un Product Backlog priorizado en Trello. Finalmente, aplicó Strategic y Tactical Domain-Driven Design para modelar los Bounded Contexts de Subscription Management, Delivery Expense Management y Premium & Billing. | **AV1:** El equipo actualizó y aplicó conocimientos de investigación de usuarios, ingeniería de requisitos, priorización ágil y diseño orientado al dominio sobre un problema concreto: la gestión de suscripciones y gastos recurrentes. Los artefactos mantienen trazabilidad entre la problemática, las entrevistas, los segmentos, las hipótesis, los requisitos y la arquitectura propuesta para CraveWallet. |
| Reconoce la necesidad del aprendizaje permanente para el desempeño profesional y el desarrollo de proyectos en soluciones de software.  | **AV1:** Para desarrollar el informe, el equipo revisó documentación y buenas prácticas de herramientas y tecnologías vinculadas a la solución, incluyendo Git y GitHub para el trabajo colaborativo, Trello para la gestión del Product Backlog, UXPressia para los Impact Maps, ExchangeRate-API para conversión de divisas, calendarios nativos para recordatorios y Stripe para la evaluación de pagos recurrentes. Las investigaciones técnicas se registraron como Spike Stories y se conectaron con las decisiones de arquitectura y los incrementos futuros. | **AV1:** El equipo reconoce que el aprendizaje continuo es necesario para validar decisiones técnicas antes de implementarlas y para adaptar el producto a nuevas herramientas, APIs y necesidades de los usuarios. Mantendrá la investigación documentada, la revisión colaborativa en GitHub y la validación con usuarios como prácticas permanentes durante las siguientes entregas de CraveWallet. |
